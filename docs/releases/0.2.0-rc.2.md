# Lagless 0.2.0-rc.2 · Windows 中文剪贴板修复

修复 Windows 桌面端粘贴中文时可能出现的乱码，保留独立 SSH 核心与终端安装方式。

## 本次修复

- 本地编辑框的系统剪贴板读写直接使用 Windows `CF_UNICODETEXT`，经 JNI 以 UTF-16 字符传递，避免经过 AWT 文本格式转换及 ANSI 代码页。
- 同步用于终端复制/粘贴与日志复制；支持中文、其他 Unicode 字符、Emoji 和多行文本，粘贴进编辑框时统一换行符。
- 原生剪贴板服务与显示渲染设置分离，选择兼容显示时仍可使用 Unicode 剪贴板。
- 剪贴板短暂被占用时有界重试；操作失败会提示，剪切仅在复制成功后删除选区。
- 其他平台及缺少新原生库时保留 AWT 兼容路径；私有测试剪贴板继续使用 Java 路径，不读取系统剪贴板。

## Windows x64 下载

- **推荐：** `lagless-desktop-native-0.2.0-rc.2-windows-x64.zip`，完整解压后双击 `Lagless.exe`，无需安装 Java。
- `lagless-0.2.0-rc.2-windows-x64.zip`：带精简 Java 运行时的桌面包，通过 `lagless.cmd gui` 启动。
- `lagless-terminal-0.2.0-rc.2-windows-x64.zip`：独立终端及运行时，无需图形客户端。
- `lagless.jar` / `lagless-terminal.jar`：桌面与终端可运行 JAR，需要 Java 21+。
- `lagless-core.jar`：独立核心库，依赖由项目 Maven 配置描述。
- `SHA256SUMS.txt`：附件 SHA-256 校验值。

**修复涉及 `Lagless.exe` / 桌面 JAR 与 `lagless-render.dll`：请使用完整新版桌面包，不要仅复制 EXE 或 JAR 到旧目录。** 旧原生库缺少新接口时会使用兼容路径，无法获得此次原生剪贴板修复。
