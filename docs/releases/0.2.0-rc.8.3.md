# Lagless 0.2.0-rc.8.3 · 更新进度、缓存续传与安装修复

本次为小版本更新。点击「下载更新」后立即显示状态，连接、检查版本、下载、校验解压和准备安装助手都有明确提示。下载时显示百分比、已下载/总大小、平均速度；大小未知时显示已下载量和动态进度条，暂无新数据时显示等待秒数。文件传输和校验保持在后台，界面按 150 毫秒合并刷新，不把每个网络块排入界面线程。

同一次程序运行中重开更新窗口会返回原任务及进度。任务进行时禁用重复下载、导入和回滚，完成或失败后恢复按钮，失败原因同时显示在窗口并写入本次软件日志。

原生更新包按发布版本、平台、附件标识保存到安装目录 `.updates/downloads`，或无写入权限时对应的用户更新缓存目录。已完整下载的同一附件直接复用，再核对文件大小、解压后的每个受管理文件 SHA-256、平台和版本；已有等待应用的更新直接提示重启，不重复下载。完整缓存只有校验失败时才清除并重新下载。

未完成下载保留已有内容和附件标识，再次下载时使用 HTTP Range/If-Range 尝试续传，进度从已有字节数继续。校验 Content-Range 起点、总大小和服务器校验标记；服务器不支持续传、响应不匹配或范围不可用时，明确提示并重新下载，避免把两个不同文件拼接。行为依据 [HTTP Range 规范](https://www.rfc-editor.org/rfc/rfc9110.html#name-range-requests)。不同版本或被重新上传的附件不会共用旧进度；已被旧版本删除的临时下载无法恢复，新缓存机制从本版开始保留。

桌面 JAR 更新共用进度和续传传输接口。独立终端的原有调用接口和低延迟 SSH 核心保持兼容，不依赖图形模块。

## 安装失败处理

用户安装日志记录了 Windows 拒绝替换 `java.dll`，另一份助手日志也记录过 `Lagless.exe` 替换失败；随后失败弹窗又出现 `BasicOptionPaneUI.createUI` 缺少反射注册。只读校验确认当前受管理文件完整恢复为 rc.8.1。现有日志不足以确定当时具体哪个进程占用文件，不能把 AccessDenied 一概视为缺少管理员权限。

本版在 Windows 安装助手中使用 [Restart Manager 文件占用查询](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmgetlist)，在旧程序退出后还要确认安装文件已释放，避免仅靠进程路径判断遗漏占用者；不会强行结束任何进程。替换被拒绝时再等待重试约 10 秒，失败时说明文件和权限/占用问题。日志记录等待、替换和完成阶段，错误结果保存完整堆栈和回滚异常；如果回滚本身失败，保留恢复备份。补全失败提示窗口所需的原生反射注册。

升级时从新更新包复制安装助手及其 DLL，回滚时使用较新的当前助手，保证安装器修复能随升级生效。**rc.8.1 的旧更新器仍会复制旧程序作为助手，无法倒过来获得本次安装修复；建议关闭全部 Lagless 实例后，手动完整解压替换 rc.8.3 原生包一次，允许系统请求的目录写入权限。**不要只替换 EXE 或 DLL。当前正在运行的安装目录未被本次开发修改。

Windows x64 附件包含原生桌面包、含运行时的桌面及终端包、三个 JAR 和 SHA256SUMS.txt。安全构建沿用 [rc.8](0.2.0-rc.8.md)：原生版为 Oracle GraalVM 25.0.4+7.1 加构建时嵌入的官方 CVE-2026-91403 证书缓解文件，不等于完整更新 GraalVM 其他安全修复；含运行时的包使用官方 Oracle JDK 25.0.5.0.2。

按用户要求仅编译打包、检查源码及产物，未运行测试、启动应用、下载真实更新或执行安装/UAC。续传与界面交互仍待用户实机确认，继续作为 Pre-release。
