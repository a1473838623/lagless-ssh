# Lagless 0.2.0-rc.8.17 · Windows preview / Windows 预发布版

A small update for the Windows desktop and the terminal edition: checking for updates no longer closes the native app, window resizes no longer close Lagless, and folder transfers show real progress.

### What changed

- Rebuilt to avoid a separate Windows native repaint crash after the update result appears. A captured crash stack identified `GDIBlitLoops.nativeBlit` on the AWT event thread. The native Windows app now disables `sun.java2d.gdiBlit` before AWT starts, using the fallback image-copy path; disabling D3D alone did not avoid this path. **Re-download and extract the complete ZIP even if you already have rc.8.17: the version number is unchanged.**
- Checking for updates closed the Windows native app on PCs without the GitHub CLI. Before contacting GitHub, the check started `gh auth token`; when `gh` was missing, the EXE crashed in `VCRUNTIME140.dll` while reporting that the program could not be started. Lagless now looks `gh` up on PATH first and starts it only when it is installed; the repository is public, so no token is needed. **Earlier native versions still contain the crash: install this one once by extracting the complete ZIP.**
- Resizing the window while typing into a full-screen program (such as Claude Code) could throw inside local echo and end the terminal edition, closing its console window. Edits made on a wider row are now clipped to the new width. If local echo ever fails again, the connection logs it and continues without prediction instead of exiting.
- Folder transfers count their size faster: the scan reuses the attributes in each folder listing instead of one extra request per file, and shows the running total while counting.
- Transfer progress shows files done out of the total and one decimal below 10 %, so a large folder no longer appears stuck at 0 %.
- The transfer queue shows each task's source (From) and destination (To); hover for the full path.

### Downloads and build provenance

- Windows x64 only: Native Image desktop ZIP, desktop and terminal ZIPs with a bundled runtime, and standalone desktop, terminal, and core JARs for Java 21+. Linux and macOS bundles are not published for this release; on those systems use the JARs with Java 21+, or the rc.8.16 bundles.
- Built by this repository's GitHub Actions workflows on GitHub's Windows runner from the tagged commit, with the official Oracle JDK 25.0.5.0.2 and, for the EXE, the hash-pinned Oracle GraalVM. All files have SHA-256 checksums in `SHA256SUMS.txt`.
- Update the Windows native edition by extracting the complete ZIP.

### Verification

- For this repaint workaround, local compilation passed. The affected PC reproduced the original GUI crash; the command-line update check alone does not exercise that repaint path. GUI confirmation of the workaround on the affected PC is still pending.
- The full Maven test suite passed before release on Linux with JDK 21 (core, terminal, and desktop, including real SSH and SFTP integration tests), plus a 20,000-run randomized resize stress test of local echo.
- On the Windows runner, the finished EXE ran its update check (`Lagless.exe --check-update`) against GitHub with `gh` removed from PATH.
- The release workflows skip the test suite to save Actions minutes. The Windows native build still runs the application once on the JVM to record Native Image metadata; beyond the update check, the finished EXE was not re-verified on the runner.

### 中文摘要

- 本次重新构建另行处理“显示检查更新结果后退出”：实际崩溃堆栈位于 AWT 绘图线程的 `GDIBlitLoops.nativeBlit`。Windows 原生版现在在 AWT 启动前关闭 `sun.java2d.gdiBlit`，使用备用图像复制路径；仅关闭 D3D 不足以避开此路径。编译已通过，受影响电脑的修复后 GUI 验证仍待确认。**版本号不变，已经安装 rc.8.17 也需要重新下载并解压完整 ZIP。**
- 修复 Windows 原生版在未安装 GitHub CLI 的电脑上检查更新时闪退：检查前会运行 `gh auth token`，`gh` 不存在时 EXE 在 `VCRUNTIME140.dll` 中崩溃。现在会先在 PATH 中查找 `gh`，找到才运行（仓库公开，无需令牌）。**旧的原生版本仍有此问题，请手动解压完整 ZIP 安装本版一次。**
- 在全屏程序（如 Claude Code）中输入时调整窗口大小，本地回显可能出错并导致终端版退出、关闭控制台窗口。现已修复：在较宽行上的编辑会按新宽度裁剪；即使本地回显再出错，连接也会记录并在不预测的情况下继续，而不是退出。
- 文件夹传输统计大小更快（复用目录列表中的属性，不再为每个文件额外请求），统计期间显示已找到的总量。
- 传输进度显示已完成/总文件数，低于 10% 时保留一位小数，大文件夹不再一直显示 0%。
- 传输队列显示每个任务的来源和目标，悬停可查看完整路径。
- 本版仅提供 Windows 安装包和独立 JAR；Linux、macOS 请使用 JAR（需 Java 21+）或 rc.8.16 的安装包。发布流程为节省 GitHub Actions 额度跳过了测试，测试已在发布前于本地完成。
