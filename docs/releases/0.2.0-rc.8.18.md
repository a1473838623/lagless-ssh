# Lagless 0.2.0-rc.8.18 · Windows preview / Windows 预发布版

Much faster transfers in the file manager, especially for folders with many small files.

### What changed

- Transfers start at once instead of first counting the size of every file. One SFTP channel walks the folders and queues each file as soon as it is found, while up to five more channels transfer files at the same time, sharing one speed limit. The queue shows growing totals with a "+" until the walk finishes.
- New option **Folders as one archive** in the file manager (off by default). A folder travels as one compressed tar stream and is unpacked as it arrives, so no archive file is written on either side and nothing needs cleaning up. It needs `tar` and `gzip` on the server; single files always transfer normally. When downloading, every file is still checked and staged locally; when uploading, the server's `tar` writes the files and overwrites existing files in the target folder.
- The file manager no longer has a default speed limit (it was 256 KiB/s). Leave the field empty or enter 0 for no limit.
- Each SFTP file read keeps 64 requests in flight instead of 4, which matters on high-latency links.

Measured against a real OpenSSH server at about a 50 ms round trip, 2,000 small files (11 MB): serial transfer (previous versions) 634 s to download and 622 s to upload; parallel with 4 channels 139 s and 161 s (this release uses 6); archive mode 0.9 s and 1.0 s. All copies were byte-identical and no `.part` or archive files were left behind.

### Downloads and build provenance

- Windows x64 only: Native Image desktop ZIP, desktop and terminal ZIPs with a bundled runtime, and standalone desktop, terminal, and core JARs for Java 21+. On Linux or macOS use the JARs with Java 21+, or the rc.8.16 bundles.
- Built by this repository's GitHub Actions workflows on GitHub's Windows runner from the tagged commit, with the official Oracle JDK 25.0.5.0.2 and, for the EXE, the hash-pinned Oracle GraalVM. All files have SHA-256 checksums in `SHA256SUMS.txt`.
- Update the Windows native edition with Check for updates, or by extracting the complete ZIP.

### Verification

- The full Maven test suite passed before release on Linux with JDK 21, including a 120-file parallel SFTP round trip, tar compatibility with the system `tar`, and archive path-safety checks.
- On the Windows runner, the finished EXE ran its update check against GitHub with `gh` removed from PATH. The test suite is not run on GitHub, to save Actions minutes.

- 文件管理传输明显加快：不再先统计全部文件大小，而是一边遍历文件夹一边传输；最多 6 个 SFTP 通道并行传输，共享同一限速。遍历完成前，队列中的总量带 “+”。

- 文件管理默认不再限速（原为 256 KiB/s），留空或填 0 即不限速；每个文件的 SFTP 读取同时保持 64 个请求，高延迟网络下更快。
- 在约 50 ms 往返延迟下传输 2000 个小文件：逐个传输约 634 秒，并行（4 通道）约 139 秒，打包模式约 1 秒。
