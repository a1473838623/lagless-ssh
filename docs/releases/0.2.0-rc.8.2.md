# Lagless 0.2.0-rc.8.2 · 中文排版黑屏修复与光标调整

本版为 rc.8.1 的小版本修复。

## 黑屏卡顿原因及修复

安装目录的 rc.8.1 全部 35 个受管理文件与清单的 SHA-256 一致，未发现安装文件缺失或混装。用户本机 2026-10-22 20:43:04（UTC+8）的错误日志记录：`MissingForeignRegistrationError: Cannot perform downcall with leaf type (long,long)long`，首个失败位置是 `sun.font.HBShaper.<clinit>`。随后至 20:44:43，AWT 绘制线程反复出现 `Could not initialize class sun.font.HBShaper`，堆栈经过 Swing 输入法组合文字绘制。这是原生包缺少 JDK 25 HarfBuzz 排版引擎的 FFM 调用注册，首次进入相应文字排版路径后初始化失败，后续绘制持续失败；足以解释该次黑屏卡顿。该时间段软件日志没有 SSH 断联记录，Windows 应用事件日志也未查到 Lagless 崩溃或挂起事件；不能据此排除其他尚未记录的卡顿原因。

本版补齐实际构建 JDK 源码中 HarfBuzz 使用的全部 5 种 downcall 和 5 种 upcall 签名（横向和纵向 advance 回调共用一种签名），并注册其动态查找的 Java 回调方法。仅 JNI 注册不足以覆盖 FFM。方案依据 [GraalVM 官方 FFM 文档](https://www.graalvm.org/jdk25/reference-manual/native-image/native-code-interoperability/ffm-api/)，未绕过文字排版或关闭中文输入法。

## 软件日志按程序运行归档

每次启动至退出形成一份完整的软件日志，统一记录版本、安装路径、进程号、所有窗口的本地操作、连接事件、后台操作失败和未捕获异常完整堆栈。SSH 名称只是事件来源，不按 SSH 窗口分割软件日志。关闭最后一个窗口后，等待连接关闭和待写命令日志落盘，再写入程序退出记录、关闭本次日志；关闭某个 SSH 标签或新增工作区窗口不会另建软件日志。

查看软件日志默认打开并跟随「本次运行」，列表只按运行时间显示软件运行记录，不增加旧版异常日志入口。旧版本按连接记录的本地命令另列为历史类别，不混入新软件运行日志。新版本的异常正常写入本次软件日志，只有该日志自身不可写时才尝试备用错误文件。

对连续相同未捕获异常限流：首条保留完整堆栈，持续发生时每 5 秒再次记录堆栈与上次重复次数，避免每次失败重绘都写入磁盘。原有日志文件不修改、不删除。

## 光标

Windows 原生绘制和兼容绘制均按文字基线、可见大写字形高度确定光标中心，避免行框下方的下降部留白把光标推低；光标上下各延长一点，并对齐像素边界、限制在当前行内。闪烁行为保持。

## 构建与附件

沿用 [rc.8 安全构建方案](0.2.0-rc.8.md)：原生 EXE 基于 Oracle GraalVM 25.0.4+7.1，构建时应用并嵌入官方证书阻止文件，缓解 CVE-2026-91403；这不等于完整更新基础 GraalVM 的其他安全补丁。桌面及终端运行时包使用官方 Oracle JDK 25.0.5.0.2。

Windows x64 附件包含原生桌面 ZIP、含运行时的桌面及终端 ZIP、三个独立 JAR 和 SHA256SUMS.txt。原生版应使用完整 ZIP 更新，不能只替换渲染 DLL。

按用户要求只编译打包、检查源码和产物，未运行测试、启动应用、连接 SSH、操作剪贴板或执行真实安装更新。当前运行中的安装目录和连接未改动；修复后的输入法和光标实际表现仍需用户确认，因此继续作为 Pre-release。
