# Lagless 0.2.0-rc.8.24 · Windows preview / Windows 预发布版

Two fixes: repeated output when scrolling up, and text lost when Claude Code asks a question. The second was prepared as rc.8.23, which was built but never published.

### What changed

- After a command printed more than one screen of output (such as `cat file`), scrolling up showed the output a second time, starting right after the blank prompt (`root# `). Lagless keeps a copy of the current screen for the terminal history log, and the scrolled view drew that copy and then the screen itself. The copy is no longer treated as extra rows while ordinary output is on screen, so each row appears once. The live screen and the history log were always correct. A selection on the live screen also no longer shifts when that copy changes size.
- In Claude Code, text typed at the empty input prompt was lost when Claude Code then showed a question with options (such as a permission prompt) and you chose one. Lagless keeps such text locally until Enter. Claude Code hides the cursor while a question is shown, and Lagless only noticed the prompt had gone while the cursor was visible, so it kept drawing your text over the question and took the keys meant for it: an arrow key sent the text into the question, where it was lost, and a digit was added to the text instead of choosing an option.
- Now, when the prompt row shows something else with the cursor hidden, your text steps aside: the question stays visible, the keys that choose an option go to Claude Code, and the text comes back, still unsent, when the prompt returns. The row must show other content for at least 150 ms, so a screen redraw is not taken for a question.

### Downloads and build provenance

- Windows x64 only: Native Image desktop ZIP, desktop and terminal ZIPs with a bundled runtime, and standalone desktop, terminal, and core JARs for Java 21+. On Linux or macOS use the JARs with Java 21+, or the rc.8.16 bundles.
- Built by this repository's GitHub Actions workflows on GitHub's Windows runner from the tagged commit, with the official Oracle JDK 25.0.5.0.2 and, for the EXE, the hash-pinned Oracle GraalVM. All files have SHA-256 checksums in `SHA256SUMS.txt`.
- Update the Windows native edition with Check for updates, or by extracting the complete ZIP.

### Verification

- The full Maven test suite passed before release on Linux with JDK 21. New tests walk the scrolled view row by row after long output, and cover choosing a Claude Code option with the arrow keys and Enter and with a digit, and a redraw that briefly replaces the prompt.
- The repeated output was reproduced against a real OpenSSH server by running `cat` on files of 10 to 400 lines. On rc.8.23's code, 24 scroll positions showed output after a blank prompt for each file longer than the screen; with this fix, none do.
- On the Windows runner, the finished EXE ran its update check against GitHub with `gh` removed from PATH. The test suite is not run on GitHub, to save Actions minutes.

### 中文摘要

- 修复命令输出超过一屏（如 `cat file`）后向上滚动时，输出紧跟在空提示符（`root# `）后再次显示的问题。Lagless 为终端历史日志保存了当前屏幕的副本，滚动视图此前先画副本再画屏幕本身；现在普通输出时副本不再算作额外的行，每行只显示一次。实时屏幕和历史日志一直是正确的。实时屏幕上的选区也不会再因该副本大小变化而偏移。
- 修复 Claude Code 中在空输入框输入文字后，Claude Code 弹出带选项的问题（如权限确认）并选择选项时，已输入文字丢失的问题。现在问题显示时文字会暂时让开，选择选项的按键发给 Claude Code，输入框恢复后文字仍在（尚未发送）。该行需显示其他内容至少 150 毫秒，避免把普通重绘误认为问题。此修复原定为 rc.8.23，该版本已构建但未发布。
