# Lagless 0.2.0-rc.8.25 · Windows preview / Windows 预发布版

A downloaded update now stays ready, however long you wait to restart.

### What changed

- After downloading an update, Restart and apply update stopped working if you waited more than 10 minutes: it reported that there was no update to apply, a manual restart installed nothing, and the update had to be downloaded again. A helper process waits for Lagless to exit before replacing its files, and it gave up after 10 minutes. It now waits as long as Lagless is open. The 10-minute limit only applies to files still in use after Lagless has exited.
- A downloaded update is also no longer lost when the helper itself goes away, for example after a reboot:
  - The next launch starts a new helper for the same files and installs the update, without downloading it again. If Lagless is installed in Program Files, Windows may show its administrator prompt at that launch. If you refuse, Lagless opens normally on the old version. A launch tries this at most twice for each update.
  - Restart and apply update, and Download update for the same version, also use the files already downloaded.
  - After an install that failed, a launch does not retry by itself; Restart and apply update does.
- With an update waiting, opening Lagless again while another window is open now opens normally, and the update installs once all windows are closed. Before, nothing appeared.
- The fix takes effect with this update itself: the update to rc.8.25 is installed by rc.8.25's helper, so it does not have the 10-minute limit.

### Downloads and build provenance

- Windows x64 only: Native Image desktop ZIP, desktop and terminal ZIPs with a bundled runtime, and standalone desktop, terminal, and core JARs for Java 21+. On Linux or macOS use the JARs with Java 21+, or the rc.8.16 bundles.
- Built by this repository's GitHub Actions workflows on GitHub's Windows runner from the tagged commit, with the official Oracle JDK 25.0.5.0.2 and, for the EXE, the hash-pinned Oracle GraalVM. All files have SHA-256 checksums in `SHA256SUMS.txt`.
- Update the Windows native edition with Check for updates, or by extracting the complete ZIP.

### Verification

- The full Maven test suite passed before release on Linux with JDK 21. New tests cover waiting for days, files still held after exit, a helper that is killed, retry limits, a failed install, damaged files, and a version installed by hand in the meantime.
- On Linux, the real helper code ran as a separate process against a test installation: the program stayed open for 11 minutes, and the update installed when it exited. In a second run the helper was killed, a new one started without a new download, and the update installed.
- Not tested on Windows: the administrator prompt path and a real reboot. On the Windows runner, the finished EXE ran its update check against GitHub with `gh` removed from PATH. The test suite is not run on GitHub, to save Actions minutes.

### 中文摘要

- 修复下载更新后超过 10 分钟未重启时，「重启并应用更新」提示没有可应用的更新、手动重启也不会安装、必须重新下载的问题。等待程序退出的更新助手此前在 10 分钟后放弃；现在只要 Lagless 还开着就一直等待，10 分钟限制只用于程序退出后文件仍被占用的情况。
- 更新助手本身消失（如重启电脑）后，已下载的更新也不再丢失：下次启动时会用已下载的文件启动新的助手并安装，无需重新下载。安装在 Program Files 时，Windows 可能在此时显示管理员权限提示；拒绝后 Lagless 仍以旧版正常打开。每个更新最多自动尝试两次。「重启并应用更新」以及下载相同版本时，也会直接使用已下载的文件。安装失败后不会在启动时自动重试，可点击「重启并应用更新」重试。
- 有更新等待时，若已有窗口打开，再次启动 Lagless 会正常打开（此前没有任何反应），全部窗口关闭后再安装。
- 本次更新本身即可生效：升级到 rc.8.25 时使用的是 rc.8.25 的更新助手，没有 10 分钟限制。
