# Lagless 0.2.0-rc.8.22 · Windows preview / Windows 预发布版

Text selection that follows the content in full-screen applications.

### What changed

- In full-screen applications (such as `less`, `vim`, or Claude Code's full-screen views), a selection now stays on the text you selected when the application scrolls. Before, the highlighted area stayed still on the screen while the text under it changed.
- Scrolling while holding the left mouse button extends the selection to the row under the pointer, so a selection can cover more than one screen.
- A selection that scrolls out of view is kept: it is highlighted again when you scroll back, and copying includes the rows that are out of view.
- Lagless sees a scroll by finding the previous screen's lines again a few rows higher or lower. Rows that do not move, such as a header or status line, are not part of the scrolling selection. A jump of a whole screen or more shares no lines with the previous screen and cannot be followed, so the selection stays where it is as before. Leaving the full-screen application or resizing the window clears the selection. Ordinary terminal output is unchanged.

### Downloads and build provenance

- Windows x64 only: Native Image desktop ZIP, desktop and terminal ZIPs with a bundled runtime, and standalone desktop, terminal, and core JARs for Java 21+. On Linux or macOS use the JARs with Java 21+, or the rc.8.16 bundles.
- Built by this repository's GitHub Actions workflows on GitHub's Windows runner from the tagged commit, with the official Oracle JDK 25.0.5.0.2 and, for the EXE, the hash-pinned Oracle GraalVM. All files have SHA-256 checksums in `SHA256SUMS.txt`.
- Update the Windows native edition with Check for updates, or by extracting the complete ZIP.

### Verification

- The full Maven test suite passed before release on Linux with JDK 21. New tests cover scroll detection with and without fixed header and status rows, a selection scrolled down, out of view and back, and dragging while the application scrolls.
- On the Windows runner, the finished EXE ran its update check against GitHub with `gh` removed from PATH. The test suite is not run on GitHub, to save Actions minutes.
