# Lagless 桌面客户端

![工作台布局预览（示例连接与输出）](media/local-editor.png)

[更多界面截图与动图](gallery.md)。图片中的主机及输出为示例数据。

启动：构建后在 Windows 运行 `lagless.cmd gui`，Linux/macOS 运行 `./lagless gui`。也可以 `java -jar desktop/target/lagless-desktop-standalone.jar gui`，但应用更新或回滚需要通过启动脚本重启才能就位。Java 21+；完整包自带运行时。Windows/macOS/Linux 共用 Swing + FlatLaf 界面和独立 `core` 模块的 `TerminalSession` 内核。只用终端可单独安装 [终端版](core.md)，不需要此图形客户端。

## 功能与边界

启动窗口居中显示在鼠标所在屏幕的可用区域内，避开任务栏。起始页、连接和辅助视图使用统一的紧凑圆角标签，当前标签为深色底，多标签超出宽度时横向滚动。左上角「关于 → GitHub 项目」直接用系统浏览器打开项目仓库；「关于 → 关于 Lagless」展示版本、项目地址，并提供打开 GitHub 的按钮。

| 需求 | 已实现 | 实际边界 |
| --- | --- | --- |
| 低延迟核心 | 本地行编辑、异步补全、本地历史、全屏回显预测，复用 CLI 内核 | 网络仍决定命令何时在远端执行；不能把物理网络延迟消掉 |
| 图形界面、多窗口、多连接 | 左上角下拉菜单、按需连接库（Ctrl+Shift+L）、高对比标签页（含起始页）、小型关闭图标、辅助视图逐个关闭或整体收起、新窗口；会话相互独立 | 不使用浏览器或本地 HTTP 服务 |
| 本地命令编辑 | 底部单行 / 右侧编辑 / 独立窗口共用草稿；Enter 或 Ctrl+Enter 发送全部文本，Shift+Enter 换行；成功提交后清空，未提交草稿自动保存；底部高度可拖动调整 | shell 与 Codex / Claude Code / tmux 交互模式均可发送；交互模式默认启用，每次确认目标；真实换行可确认合并、保留或取消 |
| SFTP | 本地/远端双栏浏览，双击进入文件夹，多选文件或文件夹上传/下载、串行队列、取消、进度及限速；每个文件暂存完成后替换目标 | 默认 256 KiB/s，为终端留带宽。断线保留 `.part`，当前版本重试从头传输；服务器不支持覆盖式 rename 时上传会报错并保留临时文件 |
| 日志 | 前台日志查看器支持分页、查找、自动换行、跟随最新和导出；SSH 输出与带时间的软件事件分别保存，每秒强制落盘 | 界面镜像有大小上限，完整日志单独保留；突然断电可能损失最后约 1 秒尚未强制写盘的数据。远端密码提示不记录本地认证输入；远端主动回显的敏感内容仍可能在日志中 |
| 自动重连 | 1/2/4/8/16/30 秒退避；断线关闭旧输入队列；正常 shell 退出不重连 | 绝不自动重放命令。正在终端行里输入的未提交内容不会跨连接发送；需长期保留的命令放进本地编辑窗 |
| 远程会话恢复 | 勾选服务器已有 tmux，当前标签断线后以同一会话名重新 attach | 不安装远程软件；无 tmux 时显示提示并启动新 shell。SSH/TCP 被彻底断开后，纯客户端不能保留服务器 PTY、进程和期间输出。tmux 恢复依赖远程进程仍存活及 scrollback 容量，并非无限日志或严格的字节级无损 |
| 后台会话 | 「会话 ▸ 后台会话…」或标签右上角按钮：经用户允许后只读检查服务器 tmux，缺少时可确认在当前终端运行安装命令；可输入名称或使用默认名新建，关闭 Lagless 后 shell 继续运行，重新打开后从列表选择重新连接或结束 | 未连接期间 tmux 把当前窗格的原始输出记录到服务器 `~/.lagless/background/<名称>/`，重连时导入本地「全量输入输出历史」（含全屏程序，每份最多最新 32 MiB）后删除；连接意外中断时开头可能重复已显示内容；只记录活动窗格 |
| 跳板 | 编辑连接时可从其他桌面和终端 SSH 配置选择跳板；优先复用已连通的 SSH，也可后台建立；CLI 支持 `-J` 和 OpenSSH `ProxyJump`、多跳 | 通过 SSH direct-tcpip 嵌套，目标主机独立验指纹和认证。服务器须允许 TCP 转发；关闭复用的跳板会导致下游断开并按配置重连 |
| 隐藏 IP | 目标 SSH 服务器看到跳板的出口 IP | 跳板仍能看到来源 IP；不能向 ISP、跳板及所有网络节点匿名，也不防其他应用泄漏来源 |
| 插件与翻译 | 独立进程插件；JVM 版另支持 Java ServiceLoader；可编辑输出镜像及自动换行；选区翻译、命令翻译 | 插件为可信本地代码，不是安全沙箱；慢插件有独立队列，过载丢弃插件事件并计数，原始日志不丢 |
| AI | 可配置 chat-completions 服务、问答、自然语言生成命令、补全；支持主动选取其他 SSH 上下文 | 需要自行配置服务。每次主动调用前预览、可删减实际请求文本；无自动上传、自动执行或逐按键网络 AI 调用；结果进入可编辑窗口 |
| 危险命令 | Shell 本地编辑提交前检查删除、格式化、磁盘写入、提权、下载执行、SQL 删除等并要求审阅 | 启发式防误操作；透传模式、vim/tmux 等程序内部输入、脚本、别名、混淆命令不能全面拦截。不是权限隔离或 shell 安全沙箱 |
| 多 SSH 协作 | 挑选多个就绪 shell 分发审阅后的命令；主动选取其他会话屏幕作为 AI 上下文；跳板互联 | 默认隔离，不自动探测内网或向其他服务器传输凭据。各目标发送非事务性，发送途中断线可能只执行部分目标；应先用幂等命令验证 |
| 账号互导 | Lagless JSON、OpenSSH config、PuTTY `.reg`、Xshell 单会话 `.xsh` | 仅连接元数据，不含厂商加密密码；PPK/私钥格式不自动转换。OpenSSH Include、Match、复杂通配符及厂商代理/脚本配置不完整迁移；应审阅导入结果。Xshell 二进制会话包 `.xts` 不支持 |
| 备份恢复更新 | 密码加密完整备份、校验后恢复、失败回滚、应用程序包备份、上一版本回滚；原生版支持整包更新 | JVM 版只在线更新 JAR；原生版更新程序及其配套库。换平台需要该平台完整包。恢复前关闭所有连接，结束后关闭所有窗口并重启 |

## 操作

1. 首次启动自动读取终端版 `lagless add` 保存在 `~/.ssh/config` 的连接，合并进桌面连接库；原有桌面账号和终端配置保留。之后可点「读取终端配置」补入新增连接，重复读取不会重复添加，也不会覆盖桌面端修改。也可添加连接或从「导入账号」选择其他配置文件。通过起始页快捷选择连接，或按 Ctrl+Shift+L 打开连接库后双击连接。连接库不常驻占用终端。未知指纹与 SSH 密码使用独立对话框。
2. 终端保持既有快捷键。Ctrl+] 可强制切换本地编辑/透传。Ctrl+Shift+C 复制选区（无选区复制当前屏），Ctrl+Shift+V / Shift+Insert 或右键菜单粘贴。末尾换行会去掉，避免粘贴即执行；含内部换行时提示合并为一行、保留换行或取消；粘贴目标始终为终端。Ctrl+V 保留给远端程序。
3. 「视图 → 本地编辑器」可切换底部单行和右侧编辑，布局偏好会保存。两者与独立窗口共用一份草稿，支持撤销；Enter / Ctrl+Enter 发送编辑框内的全部内容，Shift+Enter 插入换行。光标和选区不影响发送范围；成功进入发送队列后立即清空共享草稿。存在真实换行时，发送前可选择合并为一行（用空格连接、终端自动折行）、保留换行或取消。粘贴到本地编辑框不会自动发送；终端内粘贴则留在终端，不再转交本地编辑框，同样检查真实换行，不额外附加回车。未连接、队列满或取消危险命令确认时不清空。本地编辑框支持 Ctrl/Cmd+X/C/V/A 及右键剪切、复制、粘贴、全选；「自动换行」可从本地编辑器菜单或右键切换，底部、右侧及独立窗口同步。自动换行只影响显示，不增加文本换行；Enter 仍发送整个编辑框。底部编辑区默认一行高度，不显示横向或纵向滚动条。输入框右下角始终保留拖动柄，只允许上下调整高度。向下拖动时扩展窗口下沿和编辑区，保留终端区域高度；向上拖动收回下方空间，最小为一行。扩展受屏幕可用空间限制，最大化窗口需先还原；拖动期间固定终端画布的实际位置和高度，并将窗口高度更新合并到约 16ms 一次；画布初始化时关闭 AWT 的绘制前清背景，Direct2D 保留已呈现的帧，避免父窗口调整大小时先抹去文字。尺寸变化不补发待提交的回车，也不丢弃拖动前尚未同步的终端尺寸。放大后按需显示滚动条。右侧编辑仍可横向拖动调整宽度。
   在 Codex、Claude Code、tmux 等实时刷新或交互程序中，本地编辑器默认可发送全部文本，每次审阅确认；无需先切回 shell。可在本地编辑器操作菜单关闭或重新启用「交互程序发送（逐次确认）」。这会将文本作为当前程序的输入，请先确认输入框为空且不是密码提示。独立窗口也可翻译当前行、请求补全或翻译镜像选区。
4. 侧边辅助视图的标签带关闭按钮，右上角可整体收起；关闭只移除视图，SSH 连接、草稿、镜像和 AI 文本仍保留，可从「视图」重新打开。终端与本地编辑器使用闪烁细竖线光标；文件管理的文件夹、文件和链接使用矢量图标，随 DPI 缩放，不依赖字体符号。
5. 「视图 → 输出镜像」打开可编辑镜像，操作菜单支持自动换行（默认开启），独立窗口共用同一文档；高流量下镜像可能省略内容并显示提示，日志不依赖镜像。ANSI 控制序列会去掉，镜像是追加文本，不能精确表示 vim、进度条等屏幕重绘。
6. AI 结果只写入 AI 窗口。选中命令后从助手操作菜单选择「选区 → 草稿」，核对再发送。翻译命令从本地编辑器当前行取文本；翻译输出须先选中镜像文本。

7. 「视图 → 终端历史」只保存普通命令行的输入输出：已经滚出屏幕的行按原顺序保留，当前尚未滚出的屏幕内容保存在可替换的尾部；Codex、Claude Code 等实时刷新的全屏画面不写入这里。「视图 → 全量输入输出历史」保存完整的普通远端输出、可读的交互画面记录及已提交的本地命令。默认额外保存原始远端控制流，可从该历史窗口导出；关闭「保存原始远端输出」后只保留可读记录。为了避免保存密码，透传模式中的逐键输入和隐藏提示输入不会单独记入日志。两类历史都可滚动自动加载较早内容、跟随最新和导出。
   「视图 → 软件日志」每次程序启动至退出生成一份，统一记录全部窗口的启动、连接、断开、重连、shell 退出、传输、操作错误和界面异常完整堆栈。SSH 名称仅作为事件来源，打开时默认跟随「本次运行」。本地操作以 `[本地操作]` 标记，提交的命令以 `[本地命令]` 标记；“已提交”表示客户端已接受发送，远端执行结果以 SSH 输出为准。旧版本独立保存的本地命令日志仍留在 `desktop/commands/`，不再出现在日志查看分类中。每页最多加载 256 KiB，长日志不会一次占满界面内存。
8. 「会话 → 文件管理」打开双栏浏览器。双击进入目录，上方路径可直接输入并回车；↑ 返回上级。加载期间显示进度提示并暂时禁用该栏操作，成功和失败都会恢复，避免重复请求。两栏均提供新建文件夹、打开、复制、粘贴、剪切、重命名和需确认的永久删除；支持 Ctrl+C/X/V、F2、Delete、Enter。文件夹操作递归处理，不跟随符号链接。远端文件的「打开」先进入下载队列，完成后用本地关联软件打开副本，修改后需要主动上传。剪贴板可以在两栏间传输；跨端剪切只有在传输成功且源目录元数据未变化后才删除源文件。复制遇到重名会生成副本名，剪切遇到重名会报错，避免隐式覆盖；直接上传/下载的替换策略仍会先确认。选中本地项目后上传，选中远端项目后下载至当前本地目录。上传未选项目时可选择文件或文件夹。文件夹按文件合并，保留空目录；不跟随符号链接，限制 64 层 / 100000 项。取消只关闭传输通道，SSH 会话继续工作；已完成文件保留，失败项的 `.part` 可检查后重试。每个 SSH 标签维护独立的串行传输队列，文件管理窗口下半区展示等待、统计、进度、字节数、速度和失败原因；可继续添加、取消或重试。关闭文件管理窗口后队列继续，重新打开可查看；关闭 SSH 标签或退出程序会取消任务，队列不跨重启恢复。重试从头开始。最多保留 256 项任务，可清除已结束项。

9. 终端右侧滚动条和滚轮默认查看本地历史；Shift+PageUp/PageDown 翻页，Ctrl+End 或右键「回到最新输出」恢复跟随。查看旧内容时新输出不抢位置；继续输入会回到最新。Windows 桌面端默认通过随包的 `lagless-render.dll` 使用系统 DirectWrite / Direct2D：终端、终端回滚和日志正文直接绘制到原生窗口，每帧清除并整体呈现，不复制旧文字位图。采用系统 ClearType，Java 测量和原生绘制统一使用 Consolas 等宽字体；中文占双宽格，按字形实际宽度居中，不横向拉伸。中文输入法通过终端光标的屏幕坐标定位，拼音预编辑在本地绘制，确认后才交给 SSH。
   「视图 → 显示渲染…」可查看实际显示后端，并选择下次启动使用原生或兼容显示；后端初始化失败会回退并显示原因。其他平台、未携带原生库或选择兼容模式时继续使用 Swing；所有编辑框滚动禁用旧像素搬移，使用逐视口重画。原生渲染机制参考 [Scintilla 的 DirectWrite 路径](https://www.scintilla.org/ScintillaDoc.html#SCI_SETTECHNOLOGY)，渲染桥接代码由本项目实现，不需要另装编辑器或 Java。
   实时交互模式下，SSH 日志和终端回滚共用同一套正文合并规则：同一逻辑行的逐字增长更新已有行，短暂清屏再重画不会反复记录前缀；不同正文版本仍保留。普通 shell 的连续输出不做这种前缀合并，重复命令输出会保留。最近 512 行 / 200 万字符作为可更新尾部，每秒暂存为 `.log.pending`，超过此范围的稳定内容持续写入原日志，不限制总历史长度。正常断开/退出会合并尾部；前台查看、导出和备份会包含尾部，导出不会强行结束正在生成的句子。旧日志不会自动重写。
   「视图 → 记录全屏交互（日志和回滚）」默认开启并记住设置：开启时额外保存原始交互控制流 `.log.vt`，关闭后停止此额外记录，正文仍继续保存。两种设置下，前台日志与回滚都合并重复行和逐字前缀，不再向回滚堆入重复整屏。该机制不依赖 Claude/Codex 的菜单识别，变化的菜单或状态文字仍可能留下记录；去重后的正文不提供完整交互时序重放。
   应用启用 [同步刷新协议](https://github.com/contour-terminal/vt-extensions/blob/master/synchronized-output.md) 时，解析新输出期间保留上一完整画面，结束刷新后整体呈现。未提供刷新边界的应用使用有界的短暂重绘合并，避免清空与补画之间的空白帧；异常未结束的同步更新有超时保护。光标基于实际字体的大写字高适当加长，并以当前行格的中心定位，上下留白相等；原生与兼容显示均保留细竖线和闪烁效果。
   邻近历史页在本地缓存，绘制不持有实时输出锁；历史按行写入磁盘并保留颜色，不设固定总行数上限，内存缓存最多 2048 行 / 400 万字符。磁盘历史队列有界，过载会提示并省略展示行；会话日志独立记录。默认开启「视图 → 交互程序中用滚轮滚动内容」：检测到备用屏或原地重绘的交互程序时，普通滚轮优先使用应用已启用的 SGR / URXVT 鼠标协议，按光标所在位置发送真实滚轮事件；应用未启用时才退回 PageUp/PageDown。Shift+滚轮查看本地长期历史；在普通 shell 中滚轮继续查看本地历史。也可按 Alt+滚轮临时强制远端翻页。滚轮保留触控板小数增量，约每 16 毫秒合并发送最多 4 个滚轮报告；翻页兼容模式最多每 64 毫秒发送一页。反向滚动、键盘输入、选择文字、进入本地历史或鼠标模式变更会清除待发送的旧滚动意图；普通键盘输入不使用此清理策略。鼠标点击与拖选仍留在本地，CLI 的鼠标保护行为不变。按键翻页和滚轮翻页期间，全屏重绘只进入可读的全量输入输出历史和可选的原始控制流，不进入普通终端历史。程序是否响应翻页键取决于其自身绑定；不能恢复从未收到过、也未记录的远端内容。普通终端历史保留已滚出的输入输出行和当前屏幕尾部；全量历史额外保存实时刷新的可读画面，原始远端流可单独导出。原生文字绘制复用字形测量和数组缓冲。滚轮协议遵循 [xterm 的鼠标报告格式](https://invisible-island.net/xterm/ctlseqs/ctlseqs.html#h2-Mouse-Tracking)，分离本地滚动和应用鼠标协议的方式参考 [xterm.js 视口实现](https://github.com/xtermjs/xterm.js/blob/master/src/browser/Viewport.ts)。远端翻页仍取决于网络往返和远端程序重绘速度，不承诺网络差时也能达到本地编辑器的响应速度。
10. 「会话 → 强制键盘透传（当前连接）」对当前标签关闭提示符接管和预测，组合键交给远端，勾选状态在该标签重连时保留。本地编辑框仍完全本地；切换时 Shell 行编辑器中的未提交文字会交给远端，但不会附加回车；Claude 本地输入仍有文字或提交尚在等待时，会提示先发送/清空并等候接收，避免切换模式丢字。退出程序后取消勾选，在下一次远端提示符出现时恢复自动本地编辑。终端中的 Ctrl+X/C/V/S 属于远端程序，本地编辑框中的 Ctrl+X/C/V 属于剪贴板。连接库快捷键为 Ctrl+Shift+L，避免占用交互程序的 Ctrl+L。
   Claude 的 Ctrl+X Ctrl+S（依次按下）要求远端 Claude Code v2.1.275 或更新；它发送 Claude 已收到的草稿/队列，不能提交尚未离开 Lagless 本地编辑框的文字。Alt+V 编码为 ESC+v；图片粘贴还需让远端获得图片数据，普通 SSH 不会自动同步本地剪贴板。当前可使用文件管理上传图片，再在 Claude 中引用其远端路径。参见 [Claude 按键文档](https://code.claude.com/docs/en/interactive-mode)。

## 数据位置与备份

Windows 桌面端的本地编辑、终端粘贴和日志复制优先直接使用系统 [CF_UNICODETEXT](https://learn.microsoft.com/en-us/windows/win32/dataxchg/standard-clipboard-formats)，通过 UTF-16 字符传递文本；选择兼容显示不会停用该服务。同进程 AWT 延迟提供的文本使用其原有 Java 字符串，避免阻塞界面。剪贴板修复涉及桌面程序与 `lagless-render.dll`，升级时请使用完整新版包。其他平台或缺少新原生接口时保留 AWT 兼容路径。

`~/.lagless/desktop/accounts.json` 是账号库；`desktop/drafts/<会话 UUID>.txt` 保存每个会话的草稿；「恢复草稿」可读取先前窗口的文件；`logs/` 保存可读的全量输入输出历史 `.log`，启用原始输出时另存 `.log.vt`；`desktop/events/` 保存软件事件、本地操作和本地命令；`desktop/commands/` 兼容旧版独立命令日志；`desktop/scrollback/` 保存普通终端历史 `.log` 与随机访问 `.idx` 索引；`desktop/ui.properties` 保存编辑布局、自动换行、滚轮、显示后端和原始输出记录偏好；`history/` 保存历史；`plugins/` 保存扩展 JAR。同一主机的并发桌面会话使用不同历史文件，避免互相覆盖。磁盘占用需定期检查，客户端不会自动删除日志。

首次终端配置迁移完成后保存 `desktop/terminal-imported.json` 标记，避免将已删除的连接反复自动导回。需要重新读取时使用「读取终端配置」。导入连接保留 SSH 别名与具体地址：本机继续使用别名对应的 SSH 和 Lagless 设置；导出到没有该别名的机器时可使用具体地址。桌面端不会回写终端的 `~/.ssh/config`。连接库按添加顺序显示，编辑不会改变位置；拖动条目可手动排序，顺序保存到账号库并同步至各窗口，重启后保留。未选择连接时，编辑和删除菜单会禁用。

完整备份覆盖 `~/.lagless` 与 `~/.ssh` 内的普通文件，以及当前运行的应用 JAR 或完整原生程序包。外部路径私钥、符号链接指向内容、系统凭据库、环境变量、外部 Include 文件和 Java 运行时不包含在内。原有绝对路径不自动转换；迁移到不同用户名/操作系统后重新选择私钥路径。账号单独导出只包含连接元数据。恢复时可选择仅恢复数据；原生包的更新与恢复说明见 [原生版](native-image.md)。

单独导出账号为 JSON / OpenSSH 时会自动带上所引用的跳板账号；同名连接导出为 OpenSSH / PuTTY 时会附加编号，避免覆盖。PuTTY / Xshell 导出的连接元数据不包含跳板链。

备份使用 PBKDF2-HMAC-SHA256（210000 次）导出 AES-256 密钥；64 KiB 分块 AES-GCM 加密，每块独立认证，包含认证的结束帧，防止截断/重排。密码至少 10 位，遗忘后无法恢复。单份解压后文件上限 2 GiB / 50000 项，超过前先归档日志。备份应保存在数据目录外。

恢复先完整认证、在临时目录解包校验路径和账号版本，再覆盖同名文件；应用文件仅暂存为 `lagless.jar.new`。应用过程失败会还原已经覆盖的文件；备份之外的现有文件保留。运行中创建的备份不是跨多个文件的事务快照；需要一致状态时先关闭连接。配置内可能有令牌，完整备份必须妥善保管。

原生 EXE 版更新显示当前安装目录，下载后由助手确认就绪，再点击「重启并应用更新」完成替换并重新打开；Program Files 等目录需要允许 Windows 的管理员权限提示，拒绝时不会替换。旧版更新失败时可能需要手动完整升级一次。JAR 版更新按钮先显示可用版本，主动下载后保留 `lagless.jar.rollback`。回滚按钮将该文件准备为 `.new`，关闭所有客户端实例并用启动脚本重新启动后生效。不要在有其他 JVM 运行同一安装目录时用多个程序同时更新。直接 `java -jar` 启动不能应用暂存更新。当前桌面预发布版本为 `0.2.0-rc.8.20`，同时提供仅终端安装包；尚未发布稳定版 0.2。

## AI 配置

「AI 设置」可管理多个服务配置，每个服务填写完整 chat/completions 地址、多个模型和直接输入的 API 密钥；支持添加、编辑、删除、设为当前配置，以及按功能编辑提示词。AI 助手每次请求可选配置及该配置下的模型。翻译时在使用处填写源语言（可自动检测）和目标语言，供双向翻译；提示词可使用 `{source}`、`{target}`。公共地址须使用 HTTPS；本机与私有局域网 IPv4 地址（如 `192.0.2.97`）可使用 HTTP，但密钥在 HTTP 网络上传输时不加密。配置保存在 `desktop/assistant.json`；Windows 密钥使用当前用户的 DPAPI 保护，其他系统尽量限制文件权限；完整加密备份会将配置转为可恢复的格式。账号导出不包含密钥。旧 `assistant.properties` 可读取并迁移，但若原来使用自定义密钥环境变量，请在新界面输入密钥。

AI 助手附件支持 PNG、JPEG、GIF、WebP、UTF-8 文本和 PDF。PDF 在本机提取文字后作为提示上下文发送；每份 PDF 最多 12 MiB、300 页、最多附加 1,000,000 个提取字符。加密/损坏文件会显示错误；扫描图片 PDF 没有可提取文字时会提示，目前不含 OCR。文件读取与解析在后台执行，不阻塞窗口。PDF 解析使用 Apache PDFBox 3.0.8（[官方 Maven 配置与版本](https://pdfbox.apache.org/3.0/getting-started.html)）。

请求可能包含主机输出、路径和敏感信息；每次调用都展示可编辑的请求和上下文。支持服务的 JSON `choices[0].message.content` 响应，当前不使用流式响应。自定义插件可提供其他翻译/AI 实现。

## 验证与平台

`mvn test` 包含内核回归、界面渲染、账号互导、加密多帧备份/篡改/截断、嵌入式真实 SSH/SFTP/跳板、600ms 远端回显延迟下本地编辑、危险命令阻断、断线唤醒与自动重连不重放测试，不需要在服务器安装软件。

当前开发环境验证 Windows + Java 25；构建以 Java 21 为最低版本。仓库 CI 已配置 Windows、Linux、macOS 上 Java 21 的测试和自带运行时打包；在对应 CI 或实机运行成功之前，不应视作三个平台都已验收。现有依赖外部 sshd 的 shell/vim 端到端测试仍需按 README 设置 `LAGLESS_TEST_*` 才启用；嵌入式测试不能替代所有真实远端 shell/全屏程序测试。

插件开发见 [plugins.md](plugins.md)。

更新下载窗口显示百分比、下载量、平均速度与等待数据的时间，并区分连接、下载、校验和准备安装阶段。重开窗口保留当前任务；完整下载包校验后复用，部分下载保存到更新缓存并尝试断点续传。服务器不支持续传时会说明并重新下载。

rc.8.3 的 Windows 更新助手会等待安装文件占用者退出，替换被拒绝时短暂重试，并保留详细错误与失败回滚的恢复备份。rc.8.1 更新器自身仍复制旧助手，建议先用完整 rc.8.4 原生 ZIP 手动升级一次。
